Tailoring Pipeline

For any job the gate already marked submit or hold, this is what happens between clicking Apply and having a real, job-specific resume file in hand.

Built, tested, merged to main

The flow

Step by step

Something triggers a draft

Either you click Apply (or Override on a skipped job) on the dashboard, or, in auto mode, the background worker picks the next queued job on its own. Both paths call the exact same worker.tailor_for_apply() — there's only one implementation of this logic in the whole app.

Check for an existing resume first

A job is tailored once. If a resume row already exists for this job, that version is reused immediately — no model call, no new file. This is what makes clicking Apply twice, or the worker retrying, cheap and safe.

The model selects and rephrases — nothing more

If no resume exists yet, one LLM call runs: it reads your verified fact table and the job description, then picks which facts fit this job and rewrites them as resume bullets. Every bullet must name the exact fact id it came from, and any id that doesn't exist in your facts table gets the reply rejected and retried once. The model never invents a claim — it can only rearrange and reword what you already told it is true.

A separate step builds the actual file

render_docx() takes that output and drops it into your own resume/master.docx, replacing two marker paragraphs (<<SUMMARY>> and <<PROJECT_BULLET>>) while leaving your formatting, header, and layout untouched. No model is involved in this step — it's the same deterministic code every time.

The result is saved, never overwritten

A new row goes into the resume table — one row per generation, version-numbered like tailored-42-r1. Older versions are never replaced, so months later you can still see exactly what was sent for any job.

The draft carries that version forward

ats.submit() writes the draft application with this resume version attached. From there it shows up with a download link on the Applications page, and in full on the new Resumes page — where every bullet shows exactly which fact backs it.

What this covers. This is just the tailoring slice of v2 — per-role resumes and where they show up in the dashboard. Recruiter-message handling, calendar events, PDF export, and a "retailor this job" button were all deliberately left out of this pass; they're separate, later work.
